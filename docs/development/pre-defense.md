# Предзащита 28.10 — сценарий показа

Показ 5–7 минут на изолированном стенде. Все имена и данные синтетические, реальные ПДн и
клинические сведения не вводятся. За основу взят план из ветки форка `arena/9b9f04a8`,
адаптирован под текущий интерфейс.

## До показа

1. Собрать и поднять стенд: `docker compose --env-file .env -f infra/docker-compose.yml up -d --build`.
   Проверить `https://<host>:8443/api/ready`.
2. Два профиля браузера: врач и пациент. DevTools, cookies, `.env` и БД не показывать.
3. Заранее создать врача (через администратора) и синтетического пациента с назначенной PHQ-9 и
   одним назначением.
4. Подготовить второго врача в care team пациента, чтобы показать эскалацию отдельным коротким
   тестом (`alerts.integration.test.ts`, «escalation»), а не ждать 30 минут.

## Сценарий

1. **Минимальные права.** Врач видит только своих пациентов. Администратор видит врачей,
   привязки и журнал аудита, но не клинические данные.
2. **Приглашение.** Врач создаёт приглашение: ссылка и код показываются один раз, передаются
   разными каналами. Пациент принимает приглашение и согласие. Токен исчезает из адресной
   строки. Повторный вход на этом устройстве — по личному коду.
3. **Шкала и экстренная помощь.** Пациент заполняет PHQ-9 с ответом на п. 9 больше 0. Пациент
   сразу видит памятку экстренной помощи (доступна офлайн). Система не заключает о
   непосредственной угрозе и не предлагает ждать врача.
4. **Алерт врачу.** У врача без перезагрузки появляется красная карточка «Критично», в реестре —
   «Неподтверждённые алерты: 1». Врач нажимает «Принял(а) к сведению». В таймлайне видно
   статус и время подтверждения.
5. **Объяснимые карточки.** Карточка правила: уровень, источник, версия, входные факты,
   `unknown` для отсутствующих сведений. Предлагаемое действие ждёт решения врача (Task).
6. **Офлайн.** У пациента отключить сеть, отметить дозу: «Не отправлено: 1», «ждёт связи».
   Включить сеть: отметка сохранена один раз.
7. **Граница доступа и аудит.** Другой врач получает 403 на чужого пациента; запись об отказе
   видна администратору в журнале. Сигнал безопасности при всплеске отказов.

## Цифры для ответа на вопросы

- k6, 20 пользователей, 2 минуты: p95 97 мс, 0 ошибок, повторы без дублей ([stage-8](stage-8.md)).
- Бэкап `pg_dump | age` за 0,47 с, проверенное восстановление RTO 1,75 с; RPO — интервал бэкапов.
- Аудит безопасности №1: [`docs/security/audit-2026-10-25.md`](../security/audit-2026-10-25.md).
- Тесты: API 251, web 29, shared 8, скрипты 10; Playwright 5 сценариев.

## Честные оговорки

- Пороги маршрутизации к психиатру ждут клинического согласования; система не формирует
  рекомендацию о направлении.
- Тексты правил и срок эскалации требуют клинической проверки.
- Это не клиническая валидация и не аттестованная система для настоящих пациентов.
- Доставка в реальном времени рассчитана на один экземпляр API.
